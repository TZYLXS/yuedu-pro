# 客户端书源「反向同步」说明与验收预期

> 对应服务端：FnReader `3.1.x`（`docs/APP同步接口.md` §17）
> 客户端：`FnReaderAutoSync` + `FnReaderBridgeService`（连上服务端后每 5 分钟自动同步一次）

## 1. 目标

手机端本机书源（可能上百到上千个）与飞牛服务端双向同步：

- 手机 → 飞牛：本机新增/修改的书源推上去；本机删除的源告诉服务端删除
- 飞牛 → 手机：服务端更新过/新增的书源拉回本机

## 2. 服务端接口

| 接口 | 用途 |
| --- | --- |
| `POST /api/m/sources` | 首次接入全量推送（按 `bookSourceUrl` 合并，返回 `added/updated/duplicated/total`） |
| `GET /api/m/sources/sync?since=<毫秒>` | 拉服务端增量，返回 `{sources, serverTime, total}` |
| `POST /api/m/sources/sync` | 增量推送 + 拉回，请求体 `{updated:[…], deleted:[{bookSourceUrl,lastUpdateTime}], since}`，返回 `{applied, skipped, pull, pullDeleted, serverTime, total}` |

鉴权：`X-Api-Token` 请求头（推荐）或 `?token=`。

## 3. 客户端预期

- 首次连接：全量推一次，然后以服务端 `serverTime` 作为增量位点
- 之后每 5 分钟：推 `lastUpdateTime > since` 的源和已删除的源；拉 `pull` / `pullDeleted` 写回 Room
- 通知栏摘要：`书源同步：推 N 个　拉 M 个　飞牛 K 个`
- 失败不阻塞解析桥，只记录通知；401 提示令牌，404 说明服务端版本过旧

## 4. 404 退避（本次修复）

旧实现遇到一次 404 就把 `fnReaderNoSourceSync=1` 永久写死，之后再也不同步。
现改为**只跳过 6 小时**，成功一次后自动清除标记，服务端升级后无需重装 App。

## 5. 验收步骤

1. 手机「导入书源」到本机，确保数量 > 0
2. 桥接服务连上飞牛，等待首次「书源首次合并：上传 N 个」
3. 飞牛网页 → 书源，数量应与手机一致
4. 手机删一个书源，5 分钟后飞牛对应源消失；飞牛改一个源，手机端 5 分钟内出现改动
5. 断开服务端再连（模拟 404）→ 通知「6 小时后重试」，恢复后能自动继续
