# 接入飞牛（fnOS）书库

装好本 APK 后，可以让它直接读飞牛上的 [FnReader](https://github.com/TZYLXS/FnReader) 书架 / 书源 / 缓存，
不需要在每一台设备上都重新导入一堆书源。

原理：不在 APK 里写死接口，而是由 FnReader 生成一份 **Legado 书源**，
把「搜索 / 详情 / 目录 / 正文」四个动作映射到 FnReader 的 `/api/m/*`。

当前客户端版本 `3.4.0.1`（versionCode `3400001`），对应 FnReader `3.4.0`；`/api/m/*` 契约自 `3.0.2` 起未变，`3.3.0` 起书源同步新增 `nextSince`/`truncated` 分页与字段级合并口径，`3.4.0` 未改契约。

## 一、在飞牛上取链接

1. 打开飞牛桌面上的「阅读」（FnReader）→ 设置
2. 找到「阅读 APK 接入」区块（1.7.1 起提供）
3. 复制 **「书源导入链接」**，形如：

```
legado://import/bookSource?src=http%3A%2F%2F<飞牛IP>%2Fapp%2Flegado-web%2Fapi%2Fm%2Fbooksource%3Ftoken%3D<令牌>
```

也可以只要「书源 JSON」地址，在 App 里粘贴同样的地址。

> 令牌来自「设置 → 手机接入」，重置令牌后书源要重新导入。

## 二、在 APK 里导入

1. 手机 / 平板与飞牛同一网段（能打开飞牛网页即可）
2. 阅读 → 我的 → 书源管理 → 右上角菜单 → **网络导入** → 粘贴链接
3. 导入成功后书源列表出现「飞牛书库」
4. 书架 → 搜索 → 选「飞牛」分组，即可搜到飞牛上已配置书源里的书

## 三、接口对应（便于排障）

| 阅读里的动作 | 实际请求 |
| --- | --- |
| 搜索 | `GET /api/m/legado/search?key=&page=` |
| 详情 | `GET /api/m/legado/book?u=<b64url(bookUrl)>&s=<b64url(书源)>&n=<书名>` |
| 目录 | `GET /api/m/legado/toc?u=<b64url(bookUrl)>` |
| 正文 | `GET /api/m/content?url=<bookUrl>&index=<i>` |
| 封面 | `GET /api/m/cover?url=<bookUrl>` |

书源规则（服务端生成，APK 侧零改动）：

```json
{
  "ruleSearch":   {"bookList":"$.books[*]","name":"$.name","author":"$.author","bookUrl":"$.bookUrl","coverUrl":"$.coverUrl","kind":"$.kind","introduce":"$.intro","lastChapter":"$.lastChapter"},
  "ruleBookInfo": {"name":"$.book.name","author":"$.book.author","coverUrl":"$.book.coverUrl","kind":"$.book.kind","introduce":"$.book.intro","lastChapter":"$.book.lastChapter","tocUrl":"$.book.tocUrl"},
  "ruleToc":      {"chapterList":"$.chapters[*]","chapterName":"$.title","chapterUrl":"$.url"},
  "ruleContent":  {"content":"$.paragraphs[*]"}
}
```

## 四、常见问题

| 现象 | 处理 |
| --- | --- |
| 导入提示「格式错误」 | 链接里 `src=` 后面必须整段 URL 编码，直接复制设置页的链接，别手拼 |
| 搜索没结果 | 先在电脑端确认书源能搜到；飞牛只会用 `enabled && checkStatus=ok` 的源 |
| 打开书提示「书源不存在」 | 书源被删了，回阅读重新搜索 |
| 打开书提示「不在书架中」 | 用的是旧书签；回搜索重新点开一次会自动入架 |
| 封面空白 | 封面走 `/api/m/cover` 代理，源站防盗链时留空，不影响阅读 |

## 五、面板八项功能（服务端 FnReader 2.0.x）

| 项 | 作用 |
| --- | --- |
| ① 导入书源 | 下 `/api/m/sources.json` 一次性导入，之后搜索 / 目录 / 正文都走飞牛 |
| ② 全部同步到飞牛书架 | 本机书架全量比对：新书建进书架（`origin` 填书源真实地址）、进度回传、缺封面补推；同名同源只推一本 |
| ③ 打开飞牛阅读网页 | 直接跳飞牛网页端 |
| ④ 接入手册 | 内置同步接口 / APK 接入 / 手机接入 API |
| ⑤ 手机解析待命 | 开关前台服务，长轮询 `/api/m/remote/pending` 代解析 |
| ⑥ 接入书源桥 | 导入服务端生成的单品书源，搜索 / 详情 / 目录 / 正文全走 `/api/m/legado/*`，本机不装书源规则也能看书 |
| ⑦ 查看软总线 | `GET /api/bus`：列出已报到的设备、在线状态、累计代理解析次数 |
| ⑧ 传书到飞牛 | 选本机 pdf / mobi / azw3 / epub / txt 直推（`GET /api/ebook/upload` 现取令牌 → `POST /api/m/ebook/upload?name=…`） |

缓存上传、书源双向同步已改后台自动：连上服务端就每 5 分钟一轮，面板里不再有这两个按钮
（`POST /api/m/cache` 传 `.nb` 原文，服务端落 `cache/<书名>/`；书源按 `lastUpdateTime` 增量同步）。

## 六、软总线任务（手机代解析）

连着服务器时，前台服务长轮询 `/api/m/remote/pending`，执行完回 `POST /api/m/remote/result`：

| 类型 | 手机干什么 | 超时 |
| --- | --- | --- |
| `search` | 本机书源搜索；站点限流（如「搜索间隔15秒」）时用本机书架同源同名兜底 | 18 s |
| `toc` | 本机书源抓目录（按 `nextPage` 翻页，能拿全量） | 18 s |
| `content` | 本机书源抓正文 | 23 s |
| `rank` | 本机书源抓榜单 | 23 s |
| `bookinfo` | 详情规则补简介 / 封面 / 作者 / 分类 / 字数 / 最新章节 / 章数 | 9 s（服务端等 10 s） |
| `cover` | 2.6.17 拆分任务，只回 `coverUrl`；不支持时服务端回退 bookinfo | 20 s（当前 default；服务端等 8 s） |
| `intro` | 2.6.17 拆分任务，只回简介与元数据 | 20 s（当前 default；服务端等 8 s） |

2.0.2 起队列分开跑，2.6.13.1 起改成真线程池：`bookinfo`/`cover`/`intro`（media 类）独占一条线程池，
search / toc / content / rank 走解析线程池——Pro 按 CPU 核数自适应 6 / 4 / 3 / 2 条，A4（4 核 A53）固定 2 条，
电子书整本解析独占 1 条；搜索被慢源拖住时简介与封面照样按时回传。2.6.17 起服务端按隐藏分路由、领取锁定 30 秒、
在途上限高分 3/低分 2，重复回传 `duplicate`、非锁定回传 `stale`，客户端均不重试。

> 服务端 **2.0.2（2026-11-10）** 在 `docs/APP同步接口.md` 新增 §18「简介补全：让手机把书籍详情带回来」：
> 任务 `bookinfo`，payload `{bookUrl, source, name, author}`，回传 `intro` / `author` / `coverUrl` / `kind` /
> `wordCount` / `lastChapter` / `totalChapterNum`（全部可选，服务端只补空字段）；服务端只在
> `/api/intro` 与 `/api/detail` 抓不到时问手机，超时 10 秒、拿不到按原样返回、成功响应带 `"via": "phone"`。

> 服务端 **2.0.3 / 2.0.4（2026-11-10）** 只动目录引擎：分页上限 5 → 40 页、带循环检测，书源没写
> `nextTocUrl` 时按页面「下一页」链接兜底，没有新章节即停；客户端一行没改（`toc` 任务仍 18 秒，
> 服务端等 20 秒）。之前「单书源只回 50 章」就是只抓首页导致的，2.0.4 起实测整本目录一次回完。

> 服务端 **2.0.5 / 2.0.6（2026-11-10）** 改的是「加入书架」这条链路：加入书架后立即强制 `refresh`
> 抓完整目录（含分页），服务端后台补全并广播；有手机在线时优先走软总线（能过反爬），无设备或
> 手机失败自动回落本机解析，面板按钮与提示显示章数和来源。客户端无需改动——`toc` 任务本来就是
> 每次现抓整本（含 `nextTocUrl` 分页，18 秒），没有缓存，等同于服务端要求的 `refresh`。

> 服务端 **2.0.7 / 2.0.8 / 2.0.9（2026-11-14）** 改的是缓存目录落盘：`<下载目录>/cache` 下同一本书不再生成
> 「书名 (2)(3)…」，重复同步复用原目录；去重改为异步、只由 `/api/cache/dedupe` 触发（跨书源按「书名+作者」归并，
> 合并走 rename），NAS 上 1641 个重复目录已清到 158 个。接口、字段、鉴权、超时都没动，客户端无需改动。

> 服务端 **2.6.6 / 2.6.7（2026-11-16）**：2.6.6 把「替换·屏蔽」净化规则也应用到 `/api/m/content`，
> App 正文从此与网页一致，返回字段（`title` / `paragraphs`）不变；2.6.7 新增「离线缓存」页、
> `GET /api/ebook/export`（整本 TXT 导出）、`GET /api/update/check`（启动检查 GitHub 最新 Release），
> 三个入口都只在网页端用。两版都没动 `/api/m/*` 的路径、参数、鉴权与任务类型，客户端零改动。


> 服务端 **2.6.8（2026-11-16）**：监听从 `0.0.0.0` 换成 `::`（IPv4/IPv6 双栈），设置页「其它地址」多列出
> 本机公网 IPv6（`http://[240e:…]:1122`），手机走流量也能直连；`/api/m/info` 只是多返回一个 `ipv6Lans` 数组，
> `/api/m/*` 的路径、鉴权、任务类型、超时全未变，客户端零改动。面板里填 IPv6 地址会弹一次「请用 https」的
> 既有提醒（不拦截），公网访问本来就建议 https。

> 服务端 **2.6.9 / 2.6.10（2026-11-16）**：网页设置页把「其它地址」的 IPv4 与 IPv6 分行显示，IPv6 再拆成独立一行并
> 配独立复制按钮（IPv4 的复制只复制 IPv4，并过滤 `[::1]` 回环）；`server.js` 与 `/api/m/*` 未改，
> 任务类型、超时、鉴权全未变，客户端零改动。

## 七、`/api/bus` 设备字段（2.6.18.2 文档跟进）

面板⑦调用 `GET /api/bus`。上游 `docs/软总线调试APK.md` 新增 §6.3，明确 `devices[]` 的只读字段：

| 字段 | 含义 |
| --- | --- |
| `id` / `name` / `model` / `version` | 设备 ID、名称、机型、客户端版本 |
| `lastSeen` | 最近心跳时间（毫秒时间戳） |
| `handled` | 累计处理任务数 |
| `enabled` / `debug` / `online` | 是否启用、是否调试设备、是否在线 |
| `idle` | 距上次活动的空闲秒数 |

顶层另有 `pending`（待领取任务数）、`recent`（最近任务流水）、`usage`（任务类型计数）。
本次只补字段说明与历史快照，`/api/m/*` 契约未变，客户端代码零改动。
